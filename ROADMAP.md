## PKG-INTERACT: what is implemented, proposed and still missing

**Shared I1–I7 candidate:** canonical represented body and headless semantics, synthetic fixture distinct from real UI, persistent virtual lab, read-only observation, source-linked gesture ledger, per-session exact stop/resume, replay protection and narrow single-action parser. Recognized gestures mean *classified represented input*, not agreement, positive response, real physical feeling or animation. All canonical anatomy uses the same recognition policy: sensitivity metadata controls privacy/export, **not blanket region denial**. Supported responses may be affectionate, neutral, uncomfortable or, in appropriate adult fictional context and within model/provider limits, intimate. The model cannot grant standing consent. Exact stop must be enforced before narration. Earlier supervised CLI exposed false composite contact, stopped-contact narration, repeated affectionate paragraphs and generic body disclaimers; the later repair has only targeted test evidence so far.

**Standalone expansion code on feature branch:** `registry.py` has canonical-region aliases and separate gesture/action/expression vocabularies; `temporal.py` stores explicitly sourced append-only preference and boundary revisions only when constructed; `expression.py` distinguishes a text description from acknowledged audio/avatar output; `initiative.py` gates a Sofía-originated represented offer/contact with caller-supplied permission and stop/boundary checks. **All four associated Windows test files: 28 passed in 3.38 seconds at `0a5769a`.** They are not connected to live parser, ledger, emotional journal, renderer, goal selector or idle worker. No physical contact, voice/animation, proactive messaging, automatic preference learning, active new emotion labels or enforceable production boundary is established by them.

**Detailed I8–I16 dependency and acceptance:** [current INTERACT roadmap](docs/development/pkg-interact-roadmap.md), [component evidence](docs/development/pkg-interact-i8-i10-code-status.md), [complete embodiment/agency contract](docs/development/pkg-interact-complete-embodiment-and-agency-contract.md), [initiative and absence contract](docs/development/pkg-interact-initiative-and-idle-contract.md), [live failure evidence](docs/development/pkg-interact-live-cli-review.md). The intent includes extensive aliases, gestures/actions, changing positive/negative/ambivalent responses, laughter/crying, character initiative and separately authorized running-only idle work, with neither automatic enjoyment nor invented offline thought.

**Inter-package ownership:** INTERACT owns typed events, proposal/description distinctions and headless reactions; REL owns modeled social/emotional context; MEM owns source-verified durable promotion/correction; ACT owns actual bounded goal selection/worker/delivery; UI owns real authenticated renderer/voice; SAFE owns trusted authorization and revocation; VERIFY owns measured negative/live proof. A lab fixture cannot write production evidence or authorize a tool, screen, camera, microphone or robot.

An inferred emotional tone is not enforceable permission or a durable user preference. [Cross-package memory/continuity contract](docs/development/five-cross-package-acceptance-contracts.md).

Review code proposals, validate diffs/test results and rollback. Outbound messages require destination/channel opt-in, quiet hours, rate limits and delivery acknowledgment. Helpers need external resource limits and force-kill. [OpenCode boundary](docs/development/opencode.md).
- **UI / BODY:** text-only interaction must work with no renderer. UI must prove actual hit tests, non-click-through, recording/voice state and animation/audio acknowledgments. Gaia requires hardware verification, independent emergency stop, supervised bench tests and separately authorized actuation. Text or synthetic motion never implies motor authority.
- **SAFE / EVOLVE / VERIFY / CLEAN:** maintain protected Constitution/identity integrity, independently enforced stop and authority, audit, backup/restore, privacy retention and replay checks. Keep source evidence of fixture vs real Windows/Artemis/client/robot tests, exact SHAs, failures and latency. CLEAN changes require inventory, scoped diff, regression and recovery before deletion. [CLEAN/INTERACT contract](docs/development/package-clean-interact-lab-contracts.md).
