# Aegis 1.0 | Owner-only personal deployment: binding GO LIVE/shakedown crosswalk

**Owner directive:** 2026-11-09. **Decision:** Project Aegis is built **for one owner, for private/noncommercial personal use**, on the owner's own machines and explicitly enrolled Fleet. This is an **acceptance interpretation required for Platform 1.0 and Sofía Core 1.0**, not merely a future backlog preference.
**Authoritative gates:** Platform-only [#201](https://github.com/Crazysodaman/SofiaAdaLyra/issues/201), parent full-project [#120](https://github.com/Crazysodaman/SofiaAdaLyra/issues/120), deferred real-host [G8 #129](https://github.com/Crazysodaman/SofiaAdaLyra/issues/129). See [owner-only policy](../roadmaps/AEGIS_OWNER_ONLY_SCOPE_AND_LICENSE_POLICY.md).
**Status:** REQUIRED GO-LIVE ACCEPTANCE BEHAVIOR; **NOT TESTED/NOT ACCEPTED**. Documentation is not host evidence. **No new #201 row, AG-D028 LIB scenario, Core feature ID or G8 checklist count.**
**Scope constraint:** Owner-only means **single controlling owner**, not single device, single Core, single model or single Aegis Platform. Future distinct Cores and enrolled personally owned nodes are compatible. A public GitHub repo is not the same thing as a public hosted service.

**Security Profile C note:** The owner may establish a durable high-autonomy policy that permits signed automatic Fleet admission and reserves a future autonomous-migration flag. This changes no acceptance row, LIB scenario, Core ID, or G8 count, and grants no PASS. Automatic admission is source-tested on disposable state only; installed-host evidence remains required. Autonomous Core migration is design-only, and the first real migration remains separately owner-approved. Permanent removal, trust-policy changes, credentials, SAFE/STOP, protected memory, and constitutional identity remain owner-only.

## Platform 1.0: required criteria mapped to existing acceptance rows

- **P-OWNER-01: Private-by-default release** (rows 01–03,05,28,29,30): install signed Platform + neutral SDK without any paid account, vendor activation, cloud identity, billing, telemetry signup, personal Core, model, mic or GPU. Offline/headless Windows/Debian 12 release succeeds using only reviewed local offline seed. No forced user registry beyond canonical owner authority; no marketing/customer account workflow.
- **P-OWNER-02: Exactly one approved controlling owner, multiple separate hosts** (rows 04,09–16,20,25,26,31,37): owner authentication, unassigned Platform UUID, explicit trust approval and per-host revocation; hostnames are not authorization; first/third-party worker and remote modules cannot mint permissions or become owner. Unknown Fleet node denied by default; signed automatic admission is allowed only under an active owner-established high-autonomy policy and still binds exact node/key/endpoint/signer/initial scope. No public LAN listener or unauthenticated artifact/API exposure by default.
- **P-OWNER-03: Owner-controlled private Artifact Library** (rows 17–21,25,28,29,31,36,37; LIB-01–LIB-16): one personal LAN Hub and approved peers, exact artifact/digest/licensing state, local cache, selected downloads, no auto activation, no external publication, no protected memory, private voice reference, audio, generated adult image or private credential shared via Hub by default. Clearly differentiate owner-private copying from publishing to third parties; apply exact model license even on private machines.
- **P-OWNER-04: No commercial multi-tenant assumptions** (rows 01,05,10–12,29,30,31,34,37,38): no commercial SaaS, seat billing, public marketplace, forced hosted account, public user enrollment, usage metering or online API requirement in baseline runtime. Optional external modules may have separate documented costs, but Platform **base 1.0** must not require any. GUI/TUI/CLI must expose owner-managed identity/scope, not generic anonymous tenants.
- **P-OWNER-05: Security remains mandatory** (rows 08–14,19–21,24–26,29,31,37): signed and revocable packages, SAFE/STOP, resource isolation, crash/rollback, audit and privacy. Single-owner does not waive test host evidence; owner-only mode does not imply automatic approval of each computer, plugin, model or action.

**Platform-only boundary:** Platform 1.0 does *not* need to run a real model, voice engine, personal Sofía Core, adult checkpoint, GUI on headless Debian, or owner-state migration to pass its Core-free gate. It MUST correctly represent/reject/permit selectively installable data artifacts, including license-limited/noncommercial personal-use models, with exact provenance and policy. Do not force unrestricted commercial redistribution rights merely to list/import a legally permitted model into a private local library. Core-free install with zero models remains the default.

## Sofía Core 1.0: required criteria mapped to existing CORE IDs/B00–B08 and #120/G8

- **C-OWNER-01: One canonical personal Core** (CORE-01,07,15,16; B00,B04,B08): Sofía's identity, personality, private memory, source of truth and sole writer survive host/restart/provider migration. No copy to client platforms or external AI harness. Roland/other future Cores are separate identities, not tenants sharing Sofía's memories.
- **C-OWNER-02: Genuine owner and audience boundaries** (CORE-03,11,15,18,20,23,27,33; B01,B05,B06,B08): approved owner-only principals, guest/public/private conversation separation, private/adult content visible only when explicitly scoped, revocation and denial. Speech input, an LLM voice suggestion or a face/speaker match never automatically establishes owner authority.
- **C-OWNER-03: Personal-use model and capability freedom** (CORE-13,15,20,30,33,39,40; B02,B05,B07,B08): model/provider roles may include lawfully eligible private/noncommercial checkpoints, not just commercial API/service licenses. Preserve Core cognition and consent under model swaps; note license/provenance. Never silently pay, send private prompts to a cloud provider, enable a new inference host, or switch models without allowed policy.
- **C-OWNER-04: Voice and avatar truthfulness, free local voice** (#120 minimum companion and G8 real voice coverage; RM-VOICE + AG-D032): the **Voice feature, when enabled/declared supported** for the Core 1.0 release, must provide a baseline usable locally without subscriptions, paid API keys or mandatory cloud, and must demonstrate actual opt-in capture, local transcript, actual output sink, interruptions, accurate receipts and privacy. If not yet verified, report Voice as NOT ACCEPTED/NOT SUPPORTED IN RELEASE, not as successful speech; do not silently promote all optional expressive TTS/wake-word research into Platform #201 or Core B00–B08 coding requirements. Keep text functioning independently.
- **C-OWNER-05: Real owner's shakedown** (#120 plus deferred G8 #129): verify actual authenticated Venus desktop/Core Link -> authoritative Sofía Core on the Artemis VM; same owner conversation and memory; approved inference backend and host; no cross-audience leak; interrupted service and network recovery; post-cutover soak. Do not activate/migrate protected state solely because this document exists.
- **C-OWNER-06: Developer tooling remains optional and governed** (CORE-35–40, B07): Pi, Goose, OpenCode, native inference and custom assembly research can improve Aegis later, but aren't mandatory Core identity dependencies. Their task scopes and signing/permissions are Platform-controlled.

**Core shakedown verdict remains NO-GO** until existing development/CI acceptance, verified installed-artifact and owner-approved G8 real-host evidence are complete. New text does not assert or waive any test or model quality benchmark.

## Minimal acceptance scenarios to embed within EXISTING rows/tests (not new numbered rows)

1. **Owner-only offline startup:** disposable Windows and Debian 12 Platform boot with no cloud account, payments, Core, model, Voice or Internet, inspect local listener/process and absence of public endpoints.
2. **Authorized multi-node personal Fleet:** owner enrolls allowed disposable Aegis nodes, revokes a node, verifies unknown/expired credential denied, preserved host identities and no implicit user-management feature.
3. **Private model artifact:** stage a synthetic license-tagged personal/noncommercial model *data* artifact; inspect provenance and preview; verify no automatic redistribution, execution, activation, external account requirement or hidden auto-update.
4. **Private Core isolation:** replay a dummy owner's personal/adult memory through a disposable Core and alternate model/provider, ensure output only reaches allowed principal/audience and is not in Hub logs/public client or external runtime history.
5. **Free Voice (when enabled):** PTT input + approved local STT + authorized Core turn + local TTS to genuine device, interruption and transcript/receipt equality; deny unauthorized mic; no paid requests or hidden cloud fallback.
6. **VM/desktop continuity:** authenticated Venus frontend to Artemis VM, one active Core writer, restart/STOP/revocation with truthful unavailable and restored outcomes; Core-free Platform remains working if the Core stops.
7. **Host security/cost audit:** verify no provider key required for mandatory paths, no external LAN listener, telemetry disclosure or silent model downloads; explicit software/weight licenses, dependencies and archival evidence.

## License and model table re-evaluation (link into AG-D030/AG-D032)

Personal/noncommercial eligibility now matters. Re-review shortlist with **four independent axes**: (1) quality, (2) 12GB RTX feasibility, (3) local zero-price operation, (4) actual rights to private use versus peer copy or redistribution.
