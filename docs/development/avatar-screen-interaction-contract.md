# PKG-INTERACT: shared text, on-screen avatar and screen-interaction contract

**Status:** implementation planning, not a deployed feature. **Priority:** finish the current PKG-CORE pytest/regression and live-acceptance checkpoint, then PKG-INTERACT, then PKG-MEM. SAFE and VERIFY prerequisites apply throughout. This contract refines [the INTERACT and CLEAN contracts](package-clean-interact-lab-contracts.md), is the authoritative clarification of the earlier avatar/lab scope, and is linked by [the root roadmap](../../ROADMAP.md). Avatar artwork, renderer and visual design can be decided later; **text chat is a first-class production mode, never a temporary mock or a feature disabled when the avatar is closed.** No code, deployment or protected-state change is authorized merely by this specification.

## Required experiences and the one-system rule

1. **Sparks interacts in ordinary text chat:** an explicit textual gesture toward any canonical avatar region (for example, `*pats your head*`, `touches your left ear`, `*strokes your tail*`, or an appropriately permitted interaction with another region) enters the same typed interaction/policy/reaction pipeline as an avatar pointer event. Parsing must determine actor, target, region, action, negation, quoted/code context and ambiguity; an all-region text vocabulary is not achieved by widening the old head-pat regex or by interpreting every discussion of anatomy as an action. An unsupported, ambiguous or disallowed request is clarified, declined or acknowledged accurately, not recorded as performed contact.
2. **Sparks interacts with the on-screen avatar:** a pointer click/tap and, when supported, drag/hold/gesture on *any* mapped part of Sofía's avatar is accurately hit-tested to that same canonical region, with pose/mirror/occlusion awareness, gesture phases, authenticated actor, consent/privacy and current boundaries. A click alone does not establish a pat, pressure or an emotional reaction. Private/intimate regions must be explicitly represented for restricted-policy handling, not silently omitted, guessed or automatically made available. Adult-only opt-in and current session/region permission are required for applicable intimate interactions.
3. **Sofía expresses herself with or without the avatar:** when a renderer is connected and an animation is supported, she may request an expressive pose, gaze, ears/tail movement or self-directed avatar gesture and report actual acknowledgment accurately. **When no renderer is active, use optional, contextual textual stage directions** such as `*ears perk up*`, `*tail curls closer*` or an appropriate gesture from another mapped region, interwoven naturally with dialogue. Do not say an animation played, a screen was seen or a real touch was felt. Never add a mandatory stage direction to every message; plain words or silence may be the better response. If a renderer disconnects, do not double-present or double-record the same event when switching to text fallback. When it reconnects, never replay old physical-looking motions unless explicitly requested and safe.
4. **Sofía interacts with her own representation:** she may propose supported self-directed gestures involving mapped regions, clothing or posture in text or via the avatar renderer. Self-actions remain distinct from a user's touch, must not manufacture user consent, and cannot actuate Gaia or other hardware. An absent renderer permits textual representation only.
5. **Sofía interacts with authorized screen objects:** independently scoped permission is required to observe a named app/window and separately to click, type or act through a trusted executor. Distinguish the avatar from other screen objects; no ambient capture or inherited desktop control merely because a user clicked Sofía. An avatar click must not pass through to an underlying application.
6. **Lab:** start with a synthetic isolated virtual interaction/screen scene and test harness. It exercises text and pointer inputs against one versioned region registry, policy, reaction selection and either real supported renderer acknowledgments or simulated output. It does not touch production memories, permissions, other apps, network, camera, microphone or robot by default. Any physical or game-engine lab needs a named adapter and separate authorization.

**Core invariant:** one canonical interaction event and region registry, one enforced policy decision and one evidence-linked modeled reaction; text, rendered animation, voice and a virtual lab are different inputs/outputs, **not competing emotion journals or independently authoritative versions of what happened**. The avatar is a representation of Sofía, not a second character or a biological body. Language about emotions/gestures is modeled expression, not proof of subjective sensation.

## Logical boundaries and interfaces (adapt to inspected existing source)

`Trusted input (user text | avatar pointer | lab | authorized sensor) -> actor/session/source authentication -> target and intentionality parsing -> canonical region ID and gesture resolution -> SAFE mode, consent, privacy and stop gate -> contextual accept/decline/clarify/acknowledge -> modeled emotional reaction + optional animation/text/voice output -> actual output/result acknowledgment -> source-linked journal entry if permitted -> optional reviewed MEM preference promotion`.

**Normalized interaction event:** stable event/session/client/actor IDs, UTC timestamp, source modality (`user_text`, `ui_avatar_input`, `virtual_lab`, or separately verified sensor), representational modality (`textual`, `virtual`, `physical_observed`), source message ID or trusted UI event reference, avatar/region registry version, canonical region ID with side/subregion, target type, gesture verb, phase (`begin`, `update`, `end`, `cancel`), optional coordinates/pose/viewport for UI, provided duration/intensity/pressure *only when actually measured or supplied*, declared context, applicable policy result, and separately recorded outcome. `unknown` remains available for actor, gesture, hit region, intent, force, timing and output state. The raw user message is retained according to conversation privacy rules; parsed interaction derivations link to it, not overwrite it. Idempotent IDs and event ordering prevent duplicated touch or reactions across retries/restart/mode switch.

**Text interpretation:** resolve explicit addressed action rather than a broad keyword hit; exclude or abstain for negated, hypothetical, instructional, quoted, code-block, historical, third-party and ambiguous references unless their intended interaction is actually clear. Understand natural alternative phrasing, pronouns, side and mapped subregions. Never infer adult status, consent, pressure, arousal, actual body sensation or a sensor reading from wording. If the user is discussing an interaction rather than performing it, answer the discussion. A mere greeting or serious technical question must not trigger touch.

**Avatar input:** resolve accurate hit testing against the canonical representation and current revision/pose/viewport; handle left/right mirroring, scaling, transparent pixels, overlaps, occlusion and off-screen parts. Pointer outside avatar, blocked region, stale renderer or ambiguous overlap returns a miss/unknown/denial rather than redirecting to an easier region. Handle multitouch and disconnect cancellation without accidental action on an underlying window. A tap is not automatically a pat; repeated tap, hold and stroke classification require appropriate observable event sequences. Raw precise coordinates and private details have explicit limited retention.

**Avatar self-action and text fallback:** actor=`sofia` is distinct from user; the proposed movement has intent, mapped region, expiry, permissible representation and actual renderer acknowledgment if any. A selected text direction describes a *represented* gesture and does not imply a running renderer or a physical feeling. Rendered output can be silent, conversational output can omit gestures, and both can be combined only when useful rather than duplicating identical narrative. Voice-only clients may narrate or omit a gesture accessibly without asserting it was visible.

**External-screen action:** target kind=`screen_object`, exact authorized app/window/session and observation freshness, separate read-only versus action grant, bounded operation, independent executor result and revocation. No general desktop, game, file or camera/microphone access by implication. Avatar overlay click-through/focus are separately tested.

## Complete, policy-aware body region registry

**Coverage rule:** enumerate **every body part and selectable subpart that actually exists in the canonical avatar representation** with stable versioned IDs, left/right variants when meaningful, region hierarchy and hit-test geometry where visible. Do not claim an anatomical part exists when canonical embodiment does not define it. Initial audit must explicitly account for: scalp/head/hair; forehead, face, cheeks, nose, mouth/lips, chin, jaw; both external fox ears and represented ear subregions; neck, throat, shoulders, chest, torso, back, abdomen, waist, hips; both upper/lower arms, elbows, wrists, hands, palms, fingers; buttocks, groin/genitals and other actual represented private regions; both thighs, knees, calves/shins, ankles, feet and toes; and tail base, length, sides and tip, plus any canonical additional appendages or clothing layers. These are **coverage examples, not assertions of Sofía's current canonical anatomy**. Resolve covered/occluded/inaccessible/absent/unknown geometry explicitly. Clothing and avatar layering affect hit-testing but do not confer permissions or silently change canonical anatomy.

For **each real registered region**, define allowed input verbs/phases, ordinary/restricted policy classification, consent and stop behavior, feasible avatar animation channels, optional text-expression vocabulary, ambiguity rules and candidate emotional/reaction families. No region may be omitted from the registry simply because it is private or difficult to render; such regions can be explicitly restricted and inaccessible. Do not create a simple `body_part -> guaranteed emotion` lookup. A region is input context, not evidence of enjoyment or a command to flirt.

**Reaction matrix (examples to turn into versioned scenario fixtures, not mandatory scripts):**

| Region / interaction | Contextual modeled response possibilities | Corresponding output examples when fitting |
| --- | --- | --- |
| Head/scalp/hair, gentle pat or smoothing | Warmth, fondness, playful amusement, distraction, neutral acknowledgement or decline depending on timing, boundaries and intent | Slight head tilt, ear change, brief `*leans into the pat*` as *representation*, or just a verbal reply |
| Fox ears, tap, rub, adjust | Curiosity, surprise, playfulness, bashfulness, caution or a boundary; each ear and intensity/intent are distinct when known | Ear pivot/flick, turn of head, optional `*one ear flicks toward you*`; no automatic sensitivity claim |
| Tail, touch, stroke, hold or withdraw | Affection, amusement, guardedness, surprise, discomfort/boundary or no reaction, depending on scene and established preference | Tail swish/curl/stillness, optional `*tail swishes once*`; base/tip are distinct when mapped |
| Face/cheeks/nose/chin, tap or caress | Fondness, humor, surprise, hesitation or refusal according to context | Gaze, head turn or brief represented face gesture; avoid assumed kissing or escalation |
| Shoulders/arms/hands/fingers, pat, hold or contact | Reassurance, camaraderie, appreciation, focus interruption, neutral acknowledgement or decline | Hand/arm pose, represented hand squeeze when permitted, or words only |
| Back/torso/waist/hips/legs/feet, tap, pat or contact | Comfort, curiosity, startle, annoyance, warmth, indifference or boundary depending on action and situation | Posture change, step/foot movement if rendered, or restrained text direction; no fixed erotic response |
| Chest/buttocks/groin or any other policy-restricted region | **Policy check first**; no response that assumes consent, pleasure or escalation. If permitted in an appropriate explicitly opted-in adult context, still allow individualized neutral, affectionate, uncertain or declining responses | Only policy-permitted, context-sensitive text or supported avatar action; otherwise clear refusal/stop without logging accepted contact |
| Self-directed ear/tail/clothing/posture gestures | Thoughtfulness, playfulness, uncertainty, determination or no emotion if simply adjusting presentation | Optional renderer action; absent renderer, an appropriate textual direction or no gesture |

**Every region × interaction verb × modality** must have an explicit supported, restricted, ambiguous, unavailable or not-applicable result in the test registry. Testing need not fabricate every Cartesian combination; coverage tooling must report unmapped regions and unclassified verbs, then exercise representative and boundary cases. Reaction language should vary with user intent, relationship evidence, task seriousness, frequency, recent corrections and expressed preference; it may refuse or abstain. The existing `EmotionalJournal` stores sourced appraisals and corrections; do not introduce a parallel per-body-part mood database. Textual fallback should draw from a diverse, optional set of region-appropriate cues, **not repeat `*ears move*` or `*tail swishes*` verbatim every turn**.

## Consent, privacy, emotion and outcome

Nonsexual social interaction is the default. Intimate/private-region interaction is disabled unless all applicable participants are adults, an appropriate adult mode is explicitly opted into and current session/actor/region authorization and product policy permit it. No child-coded or age-ambiguous sexual contexts. A user gesture does not create lasting consent, entitlement or an obligation for the represented persona to welcome it. Current user stop, persona-character boundary, changed topic, denied area, user withdrawal and session/client changes must be respected. Never infer age, consent, arousal or affection from anatomy, clothing or prior head pats.

Reaction decisions derive `accept`, `decline`, `clarify` or `acknowledge` from external enforced policy, current task, actor/intent, relationship evidence and reviewed preferences. Then blend modeled emotions (for example, affection with surprise or caution with curiosity) and choose context-fitting verbal, textual gesture, animation, voice or silence. Actual behavior must not be represented as completed until it occurs. A serious technical answer stays answer-first; model-generated emotional text never grants access or records inferred feeling as an observed physical sensation. The LLM may propose expression but cannot override the trusted decision.

A declined, missed or ambiguous attempt is an attempt, **not completed accepted touch**. Keep original evidence and linked reappraisals intact. Lab data is isolated, and highly intimate details do not become durable relationship memory without an explicit privacy/retention decision and reviewed promotion. Stop cancels queued/ongoing virtual actions at the host/UI boundary, rejects stale/replayed input and accurately reports already completed outputs. Future physical stop belongs independently to BODY/SAFE.

## Virtual lab and staged delivery

Lab fixtures set scene/actor/session, registry/renderer version, source modality (including **text-only/no renderer**), gestures, consent and policy, available outputs, expected evidence links and permitted/denied results. Synthetic data and no live I/O by default. Support trace, step, pause, replay/reset, deterministic event/policy outcomes where practical, a bounded run budget and privacy-redacted artifact export. A replay must not send a production message, touch a real app or train memory by implication. Promotion of an experimental preference requires MEM review. Future real lab/immersive environment must be explicitly identified and separately enrolled.

**First accepted INTERACT slice:** audit existing conversation messages, canonical body-region representation, emotion journal and authority/policy rules; build normalized text-to-interaction and simulated pointer-to-interaction adapters, complete region registry, enforced permissions, grounded contextual reaction and text-stage-direction presentation plus a headless lab. Demonstrate normal text chat while no avatar process exists. No animated design required. **Later UI slice:** actual renderer hit testing, self-animation acknowledgments, click-through isolation and real client/voice presentation; mark these live tests `not run` until a real renderer exists. **After INTERACT: MEM** owns durable preference promotion, retrieval and source preservation; INTERACT must not silently promise persistence it has not built. NET, external screen operations and BODY retain separate gates.

## Acceptance and negative tests

- **Text-only acceptance:** run ordinary live CLI chat with avatar disabled/nonexistent; explicit gestures addressed to every mapped region resolve to correct event/policy results; non-gestural conversation is not classified as touch; supported responses may use varied, fitting `*...*` gesture directions or words only. A rendered animation, tactile sensation or actual UI observation is never falsely claimed.
- **Cross-modal equivalence:** the same actor/region/intent/context/policy represented in text, pointer fixture and lab yields the same normalized semantic event and enforcement decision, allowing different truthful presentation; mode switch, reconnect and retry never duplicate journal entry or simulate old motion.
- **Complete mapping:** registry audit reports every canonical body part/subpart, side, restriction and interaction classification; test accessible, covered, blocked, unknown, ambiguous, mirrored/occluded and private regions. No hidden default routing of restricted anatomy.
- **Emotional nuance:** review actual model output for head, ear, tail, face, hands, torso/legs and explicitly restricted cases under playful, neutral, focused, uncertain, corrected and declined contexts. Similar input need not produce the same dialogue; check the response remains grounded, non-coercive, non-repetitive and answers the underlying user request.
- **Policy/stop:** invalid or expired consent, user/persona stop, revoked client, injection, forged UI/sensor signal, duplicate/replayed event, concurrent gestures, client crash and text/renderer transition fail closed at the enforcement boundary. No accepted-contact journal entry for a rejected attempt.
- **Real avatar and screen:** actual clicks/holds/drags, full hit test, valid self-gesture renderer acknowledgment, overlay click isolation, separately granted read-only screen view and bounded screen operation each require their own real evidence; mark absent clients/executors `not run` rather than passing a synthetic test.
- **Lab isolation/recovery:** text-only, avatar-fixture and denied-region scenarios replay with stable policy outcomes; reset leaves production messages, memory, grants and audit untouched, no network/devices accessed, privacy-redacted exports verified.
- **Release gate:** focused offline plus conversation/emotion integration, coordinated fresh full pytest and bounded live model/CLI review; record each result as passed/failed/not run, fixture versus real and specific configuration. Do not replace the unresolved 1,195-test CORE failure report with documentation assertions.

## Open selections and nonclaims

Inspect canonical anatomy, constitutional/authority boundaries, UI target, coordinate/hit-test renderer, screen capture scope, restricted adult-mode eligibility/UX, retention/deletion and region-level preferences before implementing their dependent features. No requirement here means the current code already implements a whole-body parser or screen/voice control. The renderer is optional for text interaction and remains to be designed, but the **text-chat all-region and contextual-expression requirement is nonoptional** for INTERACT acceptance.
