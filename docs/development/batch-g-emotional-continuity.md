# Batch G: personality, emotional continuity, and reflection

**Status: active feature branch, not complete or merged.** The G acceptance decision is separate from Engineering 22's Artemis deployment and Memory K/23.

## Implemented, with boundaries

- Provider-neutral expression guidance supports contextual warmth, blended modeled emotions and optional representational fox gestures related to the current emotion, not an obligatory opening. Identity, real-world actions, capabilities and permissions remain authoritative outside model style. No intimacy meters.
- `EmotionalJournal` persists evidence-linked modeled appraisals with provenance (`observed`, `user_reported`, `inferred`), keeps original appraisals when corrected, and records narrow explicit affectionate cues only after a real user message has been saved. Natural `pats head` and `pats your head` work without asterisks; negated and code-block phrases are excluded.
- `ReflectionJournal` persists evidence-linked thoughts, deterministic completed UTC daily/weekly/monthly/yearly summaries of actual events, and a **durable unsent** outbox with deduplication, follow-up spacing, urgency and positive delivery acknowledgment. It does not invent offline thoughts or deliver messages. Repeated spontaneous outreach about unchanged evidence and a live notification channel are **not** present; they belong to L/Engineering 24, not a claim of completed G functionality.
- The typed observation bridge records actual workspace deltas and makes no claims about cause or authorship. A runtime/application boundary filters Sofía's own configured SQLite DB and its WAL/SHM/journal sidecars **before** producing startup awareness and cognitive context; raw snapshots and unrelated files remain intact. Test-run ingestion exists as a trusted typed API but is not wired to pytest.
- `ClarificationJournal` keeps a saved user's explanation associated with an explicitly selected recorded event, without rewriting that event or independently verifying the explanation. Natural-language event selection is **not** wired up; safe disambiguation/retrieval and reviewed promotion are later K/23 work, not a claim that free-form corrections now work.
- `ThoughtAgent` requests a text-only structured model reflection from a specific recorded event. It may abstain, store one thought, or queue one **unsent** message; its output's semantic truth is not automatically verified. `urgent` now requires an explicitly trusted `verified_worsening=True` flag **and** observed event provenance. The current idle service does not supply that flag, so it cannot escalate based merely on anxiety, emotion labels or a single incident. Evidence comparison that can justify escalation is future L/24 work.
- `IdleReflectionWorker` provides opt-in, application-lifetime reflection for recorded events, completed-period catch-up, idle waiting, durable event claims, recovery and retry. User and idle requests share a cognitive lock. Shutdown joins the worker before closing the runtime. `SOFIA_IDLE_REFLECTIONS=1` is off by default; no outbound delivery or further system inspection occurs. The worker reads at most 50 events within 366 days, so it is not general archival memory.
- `SOFIA_PERF_TRACE=1` prints content-free model timings, token counts, and conversation/idle lock waits. Missing timings show unknown, not zero. `context_tokens` is the requested configuration, not proven physical allocation. No model change or context reduction was performed.
- `python -m sofia.personality.audit` is a **read-only, content-free** SQLite check. It reports schema availability, attempt status counts, last attempt and thought times, matches between completed worker attempts and persisted model thoughts, and pending **unsent** messages. It prints no recorded event IDs or message/thought contents. A completed attempt without a matching thought may be legitimate abstention; a persisted thought by itself does not establish that it was generated by the idle worker. Missing database/schema is explicitly unknown, not fabricated zero activity.

## Boundaries for next roadmap revision
