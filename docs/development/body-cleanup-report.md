## Production reachability and canonical ownership

The default cognition matrix registry constructs BodyMatrixEvaluator and invokes
it during actual conversation evaluation. Its BODY contribution is REQUIRED for
physical robot/servo/E-stop context. There is no composition/bootstrap registration,
physical capability binding, hardware monitor adapter or production call into the
other four files. Every prototype class/function is reached only within those
four modules, package exports and test_body_package. Following callers stops at
FakeBackend/FakeStop/FakeSerial in that exclusive test module, not a production
entry point. No canonical live physical state or physical executor is removed.

## What was wrong, deleted, merged, moved, renamed, and fixed

Remove the four unconnected prototype files and their exclusive seven test cases:
being tested did not turn them into a deployed BODY subsystem. Clear their package
exports rather than leaving misleading motion APIs or compatibility aliases. Keep
the package marker and active routing evaluator. No merge/move/rename is necessary
for these two remaining responsibilities.

Update the BODY delivery contract with current implementation status. Preserve the
actual future hardware/feedback/operator/interlock/independent E-stop/watchdog and
supervised-acceptance requirements. This cleanup neither wires a physical backend
nor substitutes model text for hardware observations. Add two production registry
cases proving physical-body questions still require the BODY evidence domain.
They exercise the live MatrixCoordinator/default registry rather than directly
calling the evaluator or asserting source text.
