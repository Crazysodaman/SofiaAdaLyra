# Phase 5: embodiment cleanup

## What was there, purpose, and classification

| File | Decision | Responsibility |
| --- | --- | --- |
| `__init__.py` | KEEP, FIX exports | Canonical immutable embodiment types and store exports. |
| `model.py` | KEEP | Measurement, physical-self/clothing, available computer/robot/avatar and current embodiment values. |
| `store.py` | KEEP, RENAME class | Whole-embodiment JSON persistence, now EmbodimentStore. |
| `measurement_query.py` | KEEP | Conservative factual measurement recognition from canonical physical-self values. |

## Production trace and canonical ownership

Composition constructs the store at the configured avatar.json path and injects
it into SofiaRuntime. Runtime startup reads the authoritative design-baseline Embodiment, and active
diagnostics load that same store. Live wardrobe/clothing changes belong to the
separate avatar state store; this baseline is not a second live wardrobe writer. CognitiveContext/provider assembly and the avatar engine consume
the immutable physical/clothing/current values. Runtime measurement queries and
avatar self-fact queries call Embodiment.get_measurement, which delegates to the
single PhysicalSelf measurement tuple; neither layer creates another measurement
source. MeasurementFact and MeasurementQueryResult are typed factual projections,
not independently mutable state. Constructors/validation hooks are implicitly
reached by persistence and projection; load helpers are called by the actual startup/diagnostic load path. save and its
serializer remain the explicit whole-design authoring API, with round-trip tests;
no production bootstrap save caller is claimed. Store.path exposes the configured
persistence target for inspection and wiring checks.
Computer, robot and avatar values have distinct domain roles despite similar small
field sets and are serialized in their respective available/current sections.

## What was wrong, renamed, deleted, moved, merged, and fixed

AvatarStore named only one part of the whole Embodiment that it persists. Rename
the class to EmbodimentStore and its constructor diagnostics, package exports,
composition/runtime references, store variables, runnable
diagnostics, and every affected test/current documentation reference. The persisted
JSON keys, path setting/avatar.json filename and data are unchanged. No alias or
compatibility shim remains. Runtime constructor/internal owner now consistently
uses embodiment_store. Remove the runtime store accessor: no production consumer,
only a composition wiring check. Keep that check by inspecting the actual injected
internal owner and configured path instead of preserving an otherwise unused API.

No file merge, move, split or deletion is justified for these four active distinct
responsibilities. Keep aggregate measurement lookup: it has real runtime/query
callers and delegates to the canonical physical-self owner without deriving data.
No new validation semantics or canonical measurement values are introduced.
