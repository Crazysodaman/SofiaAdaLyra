# Phase 4: emotion cleanup

## What was there and classification

At this checkpoint's start, EMOTION contained the 1,096-line journal and 154-line
clarification store moved from personality, plus its 37-line matrix evaluator.

| File | Decision | Responsibility |
| --- | --- | --- |

## Production reachability and state ownership

EmotionalConversation constructs one EmotionalJournal and ClarificationJournal,
then records user cues, explicit return expectations and contacts. Background and
idle work record current absence appraisals and read exact relationship scope.
ThoughtAgent consumes EmotionalEvent; conversation reads current_state/current_state_prompt
and narrowed prompt_context; UI/theme/avatar influence consume the same immutable
CurrentEmotionalState/ActiveEmotion values. Matrix routing is reached through the
default cognition registry. observe_contact calls appraise_reunion; cue parsing
calls record_return_expectation; revise/recent read and write the same canonical
emotional event/revision tables. Serializer/validation/schema/connection helpers
are internal callers on these paths. Clarification recent/prompt_context joins those
same canonical events and revisions rather than owning another emotional model.

Journal alone retrieves bounded scoped evidence. derive_current_state receives
that evidence and computes scores without storing any state; current_state_prompt
renders the result. One catalog owns names, provenance weights, half-lives, tone
sets and active threshold. Personality influence now imports the same relational
background set instead of copying it. No SQL namespace, stored ID, schema or
migration was changed. Existing migration logic remains necessary for real saved
state. The supported unbound single-principal inspection path also remains used
by the explicit live-behavior diagnostic; it cannot merge multiple principals or
read audience-private state by implication.

## What was wrong, split, merged, deleted, moved, renamed, and fixed

The journal mixed immutable values, static catalogs, scoring/rendering, and actual
persistence. Extract the first three concerns into small bounded modules. The
journal becomes 832 lines, with its remaining SQL and domain writes under one
connection/schema owner; splitting those methods into a second state owner would
fragment this coherent persistence responsibility. Catalog is 51 lines, model 69,
and stateless projection 177. Keep the existing journal facade used by production.

Remove CurrentEmotionalState.primary: no source or test called it, and consumers
already need the strongest ActiveEmotion with intensity and provenance. No alias
is left. Remove the prospective EMOTION_EXTENSIONS subset in interaction.registry:
it duplicated labels now owned by the active emotion catalog and had only own-test
subset assertions. Keep the tests that actually record, revise and reject emotional
appraisals. Update all model/catalog consumers to their canonical module, including
application, personality, thought, UI and matrix tests. No compatibility module or
alternate catalog remains. No additional file move or rename was needed in this folder.
