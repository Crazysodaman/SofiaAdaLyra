# Phase 5: environment cleanup

## What was there, what it does, and file classification

Thirteen original modules (roughly 3,800 lines) own typed environmental observations,
configured/evidenced locations, deterministic clock/astronomy, provider normalization,
freshness selection, factual queries, provider context and a persistent settings CLI.

## Production traces and state ownership

Configuration reads environment_configuration_from_environ. Composition calls
create_environment_service, which checks standing provider-read capabilities before
creating adapters; URL/token lookup remains in the configured integration boundary.
Runtime owns one EnvironmentService; snapshot calls runtime_clock_snapshot, provider
observe/cache, freshness ranking and astronomy derivation. Snapshot invalidation is
called by runtime refresh/reconfiguration/shutdown paths. Provider names/observe
satisfy the shared protocol; their payload/property/forecast/unit/location helpers
are internal calls on production observe operations. The providers inspection
property remains the explicit composed-service inspection surface used by wiring
checks, not another state/cache owner.

EnvironmentSnapshot.effective_location is consumed by runtime queries, personality
influence and provider projection. Typed observation freshness and validation methods
are reached by the service and all constructed source values. ConfiguredLocation
represents settings, LocationObservation represents evidence: these have different
contracts and must not be conflated as duplicate models. User/site and runtime-host
locations stay explicitly separated. RuntimeUserSettingsStore owns persistent settings;
EnvironmentService alone owns refresh cache; EnvironmentSnapshot is the shared value
read by query, prompt, cognition, habits, avatar and contextual influence.

Runtime's EnvironmentQueryResolver invokes recognized-form checks/resolve. Its date,
time, timezone, location, forecast, indoor and astronomy branches stay deterministic.
Cognition uses environment_details_relevant/environment_prompt; the default registry
invokes EnvironmentMatrixEvaluator. Settings CLI has an explicit module entry point
and uses the same runtime settings store, not a second location source of truth.

## What was wrong, merged, split, deleted, renamed, moved, and fixed

Home Assistant and NWS independently implemented identical aware-source timestamp
parsing and equivalent number parsing. Merge them into source_timestamp/source_number
at the provider boundary and update both consumers. Remove the duplicate definitions
and unused timezone imports. Keep provider-specific unit vocabularies and malformed
payload rules: NWS WMO units and Home Assistant units are different contracts. This
change neither fabricates freshness nor loosens finite/range validation in typed models.

The 958-line query module combined a 248-line request-form catalog, a 100-line source
report and routing/answers. Split those distinct responsibilities into query_forms
and query_sources; resolver is now 638 lines with the same public methods. No inherited
mixin, compatibility exports or alternate state is added. The matrix and query catalog
serve different coarse/domain and exact/factual recognition contracts; they are not
interchangeable duplicate implementations. No file deletion, rename or move is justified
for the remaining active configuration, astronomy, normalization and presentation owners.
