# Phase 6: memory cleanup

## What was there / what it does

Twenty-one modules implemented reviewed-memory proposals/retrieval, exact source provenance, historical ChatGPT imports, and older prototype stores/views. Original definitions/imports and reference candidates are appended; lexical references were followed to application/bootstrap, composition/runtime, and the explicit import CLI.

Production chains: application MemoryReviewService -> ReviewedMemoryWorkflow -> exact ConversationStore originals -> DurableMemoryCandidateStore; composition/runtime -> MemorySystem -> retrieve_promoted -> principal-scoped PROMOTED candidates -> MemoryRecord projection. import_chatgpt CLI -> parsed exact import store -> explicit migration proposals/promotion; full export import -> historical evidence store -> private principal-scoped history retrieval. Source evidence remains distinct from reviewed derived memory.

## What was wrong / merged / deleted / renamed or moved

Production always configured reviewed memory, yet still constructed and opened the unused unreviewed MemoryStore. Its writes and fallback retrieval were exercised only by tests. Removed that owner and obsolete remember/recall path without deleting stored legacy database rows. No existing data is automatically promoted. Removed test-only views, source invalidation facade, and duplicate in-memory lifecycle registry. Merged exact-original modules into originals.py and budgeted projection into promoted_retrieval.py; repaired every source/test import without compatibility shims.

## What I fixed

Composition has one reviewed memory owner. Runtime retrieval still fails closed without a principal, excludes proposed/revoked records, and rechecks status before cognitive projection. Legacy-row exclusion regressions now seed the legacy schema directly and still prove those rows never enter cognition. Composition persistence tests now verify promoted source-backed memory survives reconstruction. Candidate lifecycle tests exercise the real durable owner. Invalid-limit coverage remains.

## What remains

Import evidence and derived reviewed memory have different roles and tables; they are not duplicate memory ownership. Exact imported payload/list/attachment inspection APIs remain bounded evidence inspection surfaces; no frontend invocation is claimed for those readers. Explicit authenticated review and CLI import remain supported. Source deletion is not claimed to trigger automatic memory revocation; individual review-service revocation remains live. No raw legacy row or model text becomes promoted memory implicitly.

## Tests / checkpoint

Compile, retired-name search and diff checks passed. Folder/import, application review/bootstrap, composition and matrix gate: **206 passed**. The disposable-probe connection cleanup regression also passed after checking the new owner. Final full suite: **3466 passed, 8 failed, 2 skipped** (121.55s). The same five unavailable-Ollama failures and three platform-assumption failures remain. Nineteen cases dedicated to retired prototype/legacy paths were removed; durable lifecycle and legacy exclusion checks were retained.
