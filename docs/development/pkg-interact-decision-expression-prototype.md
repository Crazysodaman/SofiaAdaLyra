## Three boundaries

1. **Interpret:** Reuse reviewed `ActionIntent` or `InteractionDecision` from the existing grammar. No new free-text classifier, new body policy, database writes, or sensor inputs. A real-sensor question is a separate exact synthetic fixture. A denied gesture from the canonical stop gate bypasses both model calls. Recognition is not consent.
2. **Choose:** Send canonical bounded self-state, the reviewed classification and original user text to the configured Ollama model. Require strict JSON with an in-scope `choice` and short diagnostic `reason`. An offer can be accepted, declined, clarified or met with a boundary; a described gesture can be responded to, clarified or met with a boundary. An ambiguous ear only permits clarification. Invalid/malformed responses stop before expression. A choice is *not* a stored preference, consent record, actual contact or animation.
3. **Express:** Send the same canonical context, reviewed classification, exact user text, and only the validated choice. Never insert the model's decision-stage reason into the next prompt as evidence. **Modeled emotional tone remains allowed as present-turn representational fiction**, but it must not be promoted into evidence of biological sensation, prior similar interactions, durable preference or completed contact. No fixed emotion-to-gesture mapping, forced affection, rendered animation or capability authorization. A physical-sensor question bypasses the avatar choice stage and uses verified-capability context instead.

`src/sofia/interaction/decision_expression.py` holds the pure types/request construction/validation plus a **narrow diagnostic expression audit**. The audit does not rewrite, reject, score or persist model output; it only flags likely unsupported-history, durable-preference, unverified-sensation, physical-impossibility redirect, generic-assistant redirect and offered-hug-completion patterns for human inspection. `src/sofia/interaction/decision_expression_probe.py` is an opt-in **state-free** Ollama experiment; unlike the earlier real-app probe it neither constructs `SofiaApplication` nor opens SQLite. The probe supports `--samples 1..8` (default 3) and reports per-case choice counts, audit flag counts and strict-contract failures without turning them into a quality score. `test/test_interaction_decision_expression.py` uses a stub provider, never real inference. This is NOT the exact live session and cannot establish qualitative success from a unit-test pass.

## Review gates

- From the activated venv on `feature/pkg-interact-shared-engine`, run `python -m pytest -q -x test/test_interaction_decision_expression.py` first. Stop on failure. Do not reset or clean the unrelated local changes.
- Only if green, run `python -m sofia.interaction.decision_expression_probe --samples 3`. Compare the structured choice and diagnostic reason with each final expression for the offered hug and left-ear pat; confirm that the stopped intrusive gesture never reaches Ollama and the real-sensor question does not use avatar-choice language. An invalid JSON decision is a diagnostic failure, not permission to silently make a default choice.
- **Inspect, do not auto-score**, the printed grounding flags and the raw text together. The audit is intentionally narrow and may miss or over-flag prose; human review remains authoritative. Look specifically for physical-impossibility reasoning in avatar cases, invented prior interactions or durable preferences, body sensitivity/felt touch, an offered hug narrated as already completed, and generic assistant redirects.
- If repeated decision samples understand the avatar scene but expression repeatedly invents evidence, keep the architectural split and investigate a stronger constrained-expression strategy or a different model. If decision itself repeatedly falls back to physical impossibility, investigate model choice/deeper interaction architecture instead of adding more general prompt prose.
- Before any live integration: controlled repeated-model review, broader regression suite, CORE/SAFE/privacy/concurrency review, explicit user merge approval. Keep PR #2 draft; no change to `main`, other PRs, live prompts, Constitution, identity, actual emotion journal, state/sofia.db or its backup, unrelated local Ollama test edit, or model settings. Discord, animation renderer and real sensing are not deployed here.
