# INTERACT live quality repair: evidence and verification

Status: **candidate patch only. No current-revision Windows, Ollama A/B or live acceptance results.** This document supplements `pkg-interact-live-cli-review.md`. The actual supervised Windows CLI at `412dc32` failed natural character responses despite 264 coordinated test passes. Exact stop/resume, stopped touch/hug, and compound nonexecution had acceptable **text** outputs, not independently audited ledger/physical actions.

## Confirmed source defect and changes

The legacy `EmotionalJournal.record_user_cue` assigned `(affection, appreciation, playfulness)` to Sofía whenever a narrow user phrase (including a head pat or `Good girl`) matched. A user's action or praise is **not evidence of her reaction**. In the live `ExpandedConversationService`, `_should_record_legacy_affection` now returns false for every legacy auto-cue. Existing events are **not deleted or migrated**. `context_hygiene.without_legacy_auto_affection` removes only identified legacy event JSON rows and reflection summaries containing their exact auto-generated description from *provider-bound SYSTEM context*. Other reviewed entries, conversation turns, tools and persistent state remain unchanged. This is a projection filter, not authorization or a cure for all unsupported-memory claims.

The reviewed social-action instruction now explicitly distinguishes offered from described actions and favors short in-character replies rather than a gesture interrogation or physical-body disclaimer. Personality guidance now discourages repeated generic curiosity and requires first diagnostic observations in technical replies; it specifically distinguishes `sc.exe` from the PowerShell `sc` alias. These are prompt-level candidates; model compliance is **unverified** and must not be described as deterministic enforcement.

## Repeatable no-production-state model comparison

`python -m sofia.interaction.ab_probe` builds two **synthetic, independent** requests for ear pat, offered hug, hypothetical tail/chest and Windows service diagnosis. A uses the active personality profile in a short prompt. B uses the canonical **static** `CognitiveContextAssembler`, identity, verified constitution, personality and embodiment plus reviewed INTERACT instruction where applicable. Both use the same configured Ollama model/generation options. The probe does not start Sofía, open the conversation store, read/write `state/sofia.db`, or use real conversation data; it prints synthetic inputs, prompt size and model answers to the local console. The configured Ollama backend may be local or remote according to the user's environment. B is **not** an exact capture of the failing live prompt: session history, memories, emotional/reflection journals, runtime evidence and tools are deliberately absent. Do not treat an A/B improvement as live acceptance.
