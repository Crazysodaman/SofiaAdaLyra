# Phase 2: runtime cleanup

## What was there / what it does

Five modules, 1,589 lines. `runtime.py` contained a 1,467-line runtime owner combining foundational lifecycle, authority, response assembly and matrix evidence projection. `clock.py` supplies read-only machine-clock evidence; `model.py` defines lifecycle states; `internal_workspace.py` suppresses only owned SQLite files/sidecars in conversational startup awareness; `__init__.py` exposes lazy runtime imports.

Production trace: module entrypoint/desktop/Discord → application → composition `compose` → `SofiaRuntime`; application startup/rollback/shutdown drives runtime lifecycle. Conversation services/matrix → runtime response and evidence methods → host-owned state/services → cognition/tools, subject to existing principal/privacy/authority checks. UI reads public avatar projection; application attaches presentation and refreshes environment. Filesystem orchestrator reads the authorized runtime inspector. ENVIRONMENT → runtime clock snapshot → environment prompt. Application startup → workspace normalization before conversational awareness. Matrix's routing diagnostics use string-based `getattr`, so the routing accessor is production-reachable even though direct lexical calls are absent.

## What was wrong / merged / deleted / moved

Split matrix evidence projection into `evidence.py` and response/context dispatch into `response.py`. Both functions consume the existing runtime owner, carry no parallel state model, and import its type only under TYPE_CHECKING. Public facade methods remain at their original production boundary. The readiness gate stays in the facade. User-history helpers move alongside their only response callers. AST comparison verified both moved function bodies are equivalent after changing the receiver variable and relocating the readiness check.

Deleted obsolete uncalled filesystem enable/disable compatibility methods; explicit authorization/revocation remains canonical. Deleted uncalled identity-store and filesystem-observer accessors while retaining the actual owned store/observer used during startup.

Deleted uncalled configuration-store, release-store and semantic-verifier accessors and their unused constructor-created objects. The active configuration/release/verification components retain their original owners and shared State Plane; this removes dormant duplicate service instances, not production safety checks. Deleted unused runtime imports, including `HistoryPolicy`.

Deleted `runtime_clock_prompt` and its sole fossil test. The production environment prompt already projects the same clock evidence and explicitly distinguishes host time from user timezone; existing environment prompt tests exercise that production path. No module was renamed or merged in this folder.

## What was fixed

Resource reopening previously happened outside startup's failure handler. A failure could leave the runtime STARTING with partially opened resources. Reopening now runs inside the guarded startup transition. All failures move to FAILED, clear runtime state and attempt every owned resource close. Startup and normal shutdown share one close routine. Cleanup failures attach notes to the original startup failure instead of replacing its cause.

Added three parameterized partial-open regressions (one for each store) and one cleanup-failure regression. They assert FAILED, cleared identity/runtime ID/authorization, close ordering and preservation of the initiating exception.

## What remains / canonical state

Runtime owns lifecycle, loaded identity/constitution/personality/embodiment, presentation authority, current filesystem authorization and configured subsystem references. Evidence and response modules project that state without caches or second stores. Operational/self-model projections remain derived. Runtime's store inspection properties used to verify injected composition remain intentional diagnostics; no extra production caller is claimed for them. `RuntimeState` and clock dataclass remain small because they are foundational data contracts, not abandoned subsystems.

No wider model/provider redesign or live service connection was introduced. Composition is the next folder. Historical reports remain historical inventories.
