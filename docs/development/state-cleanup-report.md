# Phase 6: state cleanup

## What was there / what it does

Twelve modules combined the live StatePlane boundary, SQLite backend, scoped JSON payload repositories, namespace catalog, atomic file writing, production schema registration, a prospective migration runner/lease, and a stale configured-file inventory. Original symbols/imports/reference candidates follow below.

Production chains: composition/runtime -> SQLiteStatePlane -> relationship/habit stores -> JsonStateRepository -> revision-checked durable records. Machine locations use the StatePlane directly. Application bootstrap, run host, desktop agent, and backup checks -> verify_production_component_schemas -> StateSchemaCoordinator.require. Identity/personality/embodiment stores and runtime child status writing use atomic_write_text. The schema/namespace/value classes support these active boundaries.

## What was wrong / merged / deleted / renamed or moved

The migration machinery was prospective implementation without executable production ownership. Its four exclusive tests preserved it. Removed runner, lease, unused migration planner/catalog, and their exports/namespace. Removed zero-caller namespace lookup/catalog; active constant specifications and internal schema checks remain. Preserved the production schema compatibility value and registration gate. Removed unused component current/record_migration methods and creation of the ledger written only by the retired runner; existing database tables are not dropped. Delete the misleading zero-caller file inventory rather than preserving a second stale state catalog.

Merged SchemaCompatibility into its live component-schema owner. Moved duplicate machine/knowledge legacy-evidence retirement into atomic_file.py and repaired location/persistence/lifecycle imports. Shared retirement preserves existing collision-free backup behavior.

## What I fixed

Production state exports now describe implemented boundaries. Startup schema checks remain fail closed; new tests verify idempotent registration and preservation/rejection of an incompatible durable revision. Actual state ownership is held by package stores and production component registration. No speculative runner is represented as an available migration command.

## What remains

StatePlane supplies storage primitives; scoped JSON repositories supply namespace policy; package owners supply domain state. These are layers, not duplicate sources. Protected JSON baselines remain intentional and use atomic replacement. Upgrades require an explicitly reviewed migration outside the retired prototype; mismatch rejection remains enforced. Existing SQLite data and older ledgers are preserved. Live relationship/habit correction APIs and optimistic revision checks remain.
