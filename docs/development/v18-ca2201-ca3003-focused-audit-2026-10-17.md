## CA-2201: typed objective validator registry

Original requirement: introduce an artifact-kind objective validator registry tied to actual brief objectives, concrete file content and capability receipts; model-provided success booleans cannot substitute for independent checks.

### Source path reviewed

- `src/sofia/life/validation.py` has a closed registry for `text_contains`, `min_bytes`, `min_words`, and `python_syntax`. Unsupported natural language returns `UNKNOWN`; every objective must pass to earn structural objective eligibility.
- It reads from an opened file descriptor, rejects symlink final components, checks the descriptor inode/size/change state, verifies original SHA-256 and a 64 MiB inspection limit. The current revision also requires the input file path to equal `revision.content_path`, preventing an identical-byte replacement path from being used as proof.
- Python syntax uses `compile(..., mode="exec")` without executing the code. This closes the `ast.parse` false-PASS case for top-level `return`, `break`, and similar invalid modules. Syntax compilation does **not** prove code safety, runtime behavior, or meeting the creative brief.
- `src/sofia/life/coordinator.py` calls the objective checker from read-only artifact inspection, critique evaluation, and experience learning. `_confirmed_artifact_run_receipt` independently checks completed RUN job status, scoped GOALS receipt, original revision, SHA-256 and byte count before some LIFE completion/learning paths.
- `src/sofia/life/procedures.py` rechecks exact current creative bytes and typed objectives before accepting a verified procedure.

### Targeted coverage / missing proofs

- Unit: `test/test_life_objective_parser_bounded.py` checks known/unknown objectives, wrong content, symlinks and path replacement, oversized/changed bytes, Unicode word count, Python syntax, non-execution, and original-path substitution.
- Integration: `test/test_life_verified_milestone_production.py`, `test/test_life_project_forge.py`, `test/test_v18_success_oracle_contract.py` exercise actual LIFE/RUN/CREATIVE and negative outcome requirements.
- **Open:** reconcile each original brief's criteria against independently reviewed validators. A model-originated trivial criterion (`min_bytes:1`) cannot imply that an open-ended original brief was fulfilled. Audit all callers and receipt binding, Windows/Linux negative tests and installed-wheel behavior against a single pinned tested revision.
- **Disposition:** source implementation substantial; Gate 4 **not accepted** until task-specific cross-platform CI and independent requirement/receipt review finish. Do not change canonical ledger status from this report alone.

## CA-3003: Windows release source layout and import identity

Original requirement: eliminate nested `release-source` pytest duplication/`ImportPathMismatchError` without suppressing tests; run the exact-SHA installed candidate wheel and save accepted evidence.

### Source path reviewed

- `.github/workflows/release-candidate.yml` stages tracked source to `$RUNNER_TEMP/sofia-release-source`, **outside** the checkout, and builds two disposable source copies rather than testing a nested checkout directory.
- `src/sofia/verify/stage_release_source.py` reconstructs reviewed Git HEAD bytes, validates each blob object SHA and rejects nonregular/symlink tree entries, case-colliding paths, redirected stage parents and a nonempty or inside-checkout target.
- The workflow compares both candidate wheel SHA-256 values, installs precisely that wheel, runs `sofia.verify.source_provenance` and then `sofia.verify.gate --phase full --installed-wheel-only`, and uploads diagnostic/release evidence.
- `src/sofia/verify/gate.py` checks installed-wheel origin, removes `PYTHONPATH`, and ensures checkout source is not substituted. `test/test_verify_release_stage_git_tree.py` covers CRLF/raw Git bytes, changed working tree, rejected nested/nonempty stage, and symlink entries.

### Acceptance still required

1. A completed **Windows Release Candidate Build** run at an exact reviewed `main` SHA, proving source stage, reproducible wheels, installed-wheel provenance, and actual full verification tests (not merely a workflow green from skipped gates).
2. Inspect logs to confirm no `ImportPathMismatchError` for `test.conftest`, `sofia.cognition.providers.test_provider` or `sofia.cognition.test_engine`; save artifact IDs and run/commit links as evidence.
3. Repeat or specifically exercise staging/path and import-duplication regressions where needed, then independently review proof against original task requirements.

**Disposition:** root cause appears addressed in checked-in workflow design; Windows exact-SHA acceptance **not yet established at this audit snapshot**. The earlier Debian release success is not a substitute for Windows acceptance.
