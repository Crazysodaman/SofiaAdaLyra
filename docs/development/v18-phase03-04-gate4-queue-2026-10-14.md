## Strict security and completion constraints

- **Phase 03:** Venus remains the sole canonical SQLite writer. A signed state-home pointer, staged restore, file lock, declared host label or Fleet acknowledgement cannot serve as an independently privileged writer fence. Pending migrations never promote themselves; require a supervised, signed and verified cutover and explicit owner authorization. If a new epoch has written, failback to an older copy must not resurrect prior data or erased memories.
- **Phase 04:** Offline operation is a client-scoped cache and explicit unsent draft where permitted, not a second cognition engine, permission store or canonical writer. Preserve device pairing, audience isolation, stable logical request IDs, bounded storage and unknown-delivery states across reconnects.
- **Gate 4:** Each original task needs Gates 1–3 plus exact pinned SHA, task-specific tests including pertinent failure paths and CI receipts with independent review. Neither a generic successful workflow nor a partial code path gives automatic Gate 4 credit. Production Gates 5–6 and the Venus→Artemis cutover are explicitly deferred.
