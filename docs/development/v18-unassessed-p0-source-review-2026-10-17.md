## Independent acceptance gates still required

1. For each implementation task, inspect its exact current production caller, canonical writer, configuration and permission pathways, then test behavior and denial/recovery cases. Source/module existence is insufficient.
2. For each design task, record the owner-approved decision and review against the original task wording, especially where an authorized architecture change superseded a proposed VM auto-provisioner.
3. For verification tasks, run original Windows/real-host tests and preserve actual test selectors, outcomes, current revision and evidence artifacts. Do not replace host traffic tests or supervised longitudinal trials with simulation.
4. Independent acceptance remains empty until task-by-task signed review and original requirements are witnessed. See `docs/development/v18-gate4-development-standard.md`.
