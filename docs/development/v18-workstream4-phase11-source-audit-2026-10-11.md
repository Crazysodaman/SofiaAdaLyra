# Workstream 4 | Phase 11 production audit and decision gate

**Recorded:** October 11, 2026. **Branch:** `main` only. **Scope:** CA-2101–2106, CA-3201–3214, CA-3901–3910, CA-4401–4407, CA-6601–6612 (49 tasks). **Acceptance:** none; tests, CI, live metrics and host changes deferred.

## Current architecture, verified from source

- `src/sofia/application/background.py` reserves optional autonomy credits transactionally through `application/optional_budget.py` before executing background work. Credits are bounded predictions, not observed GPU/CPU usage.
- `src/sofia/cognition/routing.py`, `cognition/budgets.py`, and `cognition/model_lifecycle.py` implement configured role routing, token caps, on-demand management and pressure-sensitive residency. Primary/secondary roles never create a second Sofía identity. Same physical Ollama artifact now counted once and protected from alias eviction.
- `src/sofia/cognition/model_inventory.py` reads local observed metadata; fresh digests are input facts, not verified licensing, tokenizer provenance, safe promotion or performance rankings.
- `src/sofia/verify/cognition_v2_baseline.py` has a deterministic harness explicitly disclaiming real LLM/GPU metrics. `cognition/performance.py` is opt-in and content-free; missing data is unknown, nonfinite values refused.
- `src/sofia/cognition/model_switch_plan.py` can fence canonical changes, but lacks a wired privileged provider broker and independently verified live continuity check. Do not claim safe live hot swap.

## Evidence standards, no fabricated results

A Phase 11 research/design task may get source-backed design notes without being marked production accepted. For CA-2103–2106, CA-3201, CA-3905–3906 and CA-4401–4407, real Venus/Artemis measurements, identical workload controls, data lineage and independent verification are required before setting acceptance values. Do not convert this source audit into successful benchmark or hardware proof.

## Build and owner decision order

1. Fix production-source safety and resource accounting without touching live models or host networking.
2. Establish a source-only deterministic comparison harness; use the same frozen test case IDs, independently checked expected outcomes, and stable git revision across baseline/ablation runs.
3. Collect actual Venus/Artemis cold/warm and gaming/busy resource data only during the later supervised campaign. Store unknowns and host timestamps honestly; never infer power or VRAM from a quota.
4. Review owner comfort limits for gaming competition, background model wakeups, and 7-day acceptance duration before changing defaults. The owner has not yet supplied specific latency/power thresholds; request these rather than inventing them.
5. Only after independent measured wins promote one optional subsystem at a time; rollback is the existing off/disable path, never a silent provider substitution. Leave production acceptance false until tests and live gates pass.
